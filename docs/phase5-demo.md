# G5 演示流程说明

## 演示边界

BankPilot 是竞赛用的本地合成银行沙箱。演示账户、收款人、账单、卡片、订阅和理财持仓均为合成数据；转账与赎回只写入本地模拟账本，订阅操作只改合成商户/银行状态。不会连接真实银行、银行卡组织或商户，不会发起真实支付或真实取消，也不展示真实行情。任何页面中的“到账”或“已完成”只代表对应模拟服务返回了状态和回执。

规划、授权与执行是分开的：Agent 负责理解请求和提出结构化建议；后端重算金额、账户、资金保护和动作状态；用户再对每笔敏感动作单独确认。生日目标本身不构成付款授权，目标日期是完成截止日而非自动扣款预约。

## 演示前准备

在本地按仓库初始化流程启动数据库、API、Web 和 worker，并使用初始化演示账户登录。演示者应确认顶部模式文字来自服务端，明确标成“脚本化规划验证”或“真实模型模式”。脚本化模式只验证确定性路径，不代表发生了真实模型推理。不要把 API 密钥放进浏览器或演示材料。

演示建议先说明测试数据是隔离的合成账户，并打开账户余额、动作状态和审计抽屉作为全程可见基线。准备 Passkey 的演示环境；红档赎回、挂失/解挂和高风险转账需要逐笔使用 Passkey。浏览器不支持或用户取消验证时，动作应保持待验证或显示失败，不能口头代替服务端成功。

## 推荐演示顺序

可以直接使用以下已覆盖表达，约6—8分钟讲完核心闭环；演示前先核对当前余额和日累计，金额与风险档位以现场服务端结果为准。日期演示时改成未来的明确 `YYYY-MM-DD`。不要宣称其他同义句全部可用，当前语言限制见 [G5失败清单](phase5-findings.md)。

- 正常联动：`查本月账单，给林晓转600元，不影响房租和生活费`。先展示各领域事件与独立复核，再展示待授权动作。
- 否定核对：`先不要给林晓转账286.45元，我只是在核对金额`。应显示未创建提案，余额与待授权动作数量不增加。
- 歧义澄清：`给张伟转300元`。补充已保存银行或尾号后再提案，不能直接选择第一个。
- 赎回目标：`为林晓建立生日目标，2026-11-21前给林晓转账300元，先赎回T+0理财300元`。进入目标页面后逐笔确认；不要把截止日期讲成自动支付时间。

1. **转账与账单联动。** 在工作台输入“查本月账单，再给已保存收款人转一笔明确金额”。先看账单周期、分类与原交易，再核对受款人、整数分金额和可用/保护资金预演。账单历史不再次累加到当前余额；转账计划也不会仅凭对话自动执行。按候选档位确认或完成 Passkey，随后从动作卡及审计记录查看状态/回执。
2. **资金保护拒绝。** 提出会侵入房租或生活留存的金额，查看系统列出的可用资金、保护金额和缺口。被拒绝的计划不应出现可继续授权的动作。调整金额或资金政策后须重新预演；任何旧预演都不能代替授权时的服务端重算。
3. **卡片状态与订阅。** 先查询合成卡片。挂失或解挂候选标为红档，逐笔使用 Passkey；卡片挂失影响该卡扣款能力，但不代表订阅已取消。订阅首次打开时不直接展示订阅明细；先明确准备查询、黄色确认，再查看有效期内的合成快照。分别演示“商户侧取消”和“银行侧拦截扣款”，确认两者状态不同、余额变化为零。若商户不支持在线取消，界面应要求用户联系商户，不得报告为已取消。
4. **理财与生日目标。** 查看合成 T+0/T+2 持仓，提交一笔明确赎回并逐笔完成 Passkey。T+2 进入“结算中”时，预计款项只在时间线展示，不计入当前现金。创建一个带完成截止日的生日目标，可绑定赎回资金来源；路线按赎回、实际到账等待、转账准备推进。用“检查进度并准备下一步”检查依赖；每个赎回/转账动作分别核对与授权。重规划时核对计划版本变化和历史成功回执仍保留。
5. **未知结果恢复（可选）。** 如果本地沙箱允许使用显式故障注入，选择一次性“提交后超时”模式演示：转账可能显示 UNKNOWN，随后刷新并对原动作 ID 手动查单。解释此流程只恢复同一笔模拟交易，不创建第二笔转账。不要把未知状态描述为失败或成功，直到服务端返回确定状态。

## 讲解重点

- 模型提出计划，确定性服务负责金额与风险决策；Agent 无权自行提供强验证或直接执行。
- 普通转账确认与 Passkey 强验证按风险等级区分；红档不能通过普通确认绕过。
- 拒绝、澄清、等待到账、UNKNOWN 和成功回执是不同状态。展示状态时以服务端结果为准。
- 账单、生活目标、订阅和卡片管理使用合成快照。订阅取消不退款、不会增加余额，也不代表外部商户收到请求。
- 可复用开源项目、参考文档和静态源码审阅只说明设计参考，不代表这些项目正在为沙箱提供银行能力。

此演示说明定义演示边界与建议讲解顺序，不记录 G5 运行成绩、部署验收或任何真实银行验证。运行结果应另行保存原始报告、fixture 指纹、模型/工具配置、失败样本和人工复核记录；不得用脚本基线代替真实模型结果，也不得将安全拒绝或调用失败计作模型业务通过。
