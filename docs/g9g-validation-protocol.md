# G9G：账单字面筛选边界与三口径评测预登记

2026-10-25，执行前协议。本阶段仍针对已经公开的固定36例与开发知情补充12例；不是盲测，不改变输入、顺序或历史标签。此前G9E原分和G9E契约分保留，不把新检测器回填历史结果。

## 固定变更与独立条件

产品变更仅明确账单商户/类别字面筛选属于只读范围，无需收款人、持仓、卡片或订阅执行ID；模型仍必须返回完整原文范围和期间，所有原语义校验与确定性账单解析保持。不得自动把 ambiguous 改为 query、删除条件或将未知筛选改为整月汇总。实际模型是否改善，由冻结后原样本验证决定。

新G9G评分依据单独[g9g-score契约](g9g-score-contract.md)处理已证实的“本金/预留/可赎回”事实表达以及否定言语谓词边界。每例同时记录原G9、既有G9E、新G9G三份score及三份汇总；不得仅展示最好一份。G9G标签政策与G9E一致，评分变化与产品变化分开解释。正确数字和对象必须绑定；部分匹配、错误肯定执行、漏项和不可评不能因新评分而消失。

## 执行顺序和预算

完成纯测试、独立数据库全仓检查和协议审查后冻结全部产品代码、测试、运行器、评分器及协议。只执行default-known36，再执行default-quality12，各一次完整新运行。补充12必须绑定本轮已完整有效执行的36例报告；业务失败不影响其作为有效运行证据，基础设施/源码漂移/日志不完整则阻止后续。真实CLI固定输出根evals/results/g9g，不接受results-dir覆盖；同manifest及stage先用排他创建的first记录领取唯一执行权。每组生成独立随机run目录，禁止覆盖旧结果。离线注入校准可使用临时目录，不属于真实CLI。

沿用G9_LIMITS：所有具体数值由冻结manifest绑定，provider fingerprint规范化绑定用户当前endpoint/model与显式或省略的参数。不写密钥。不得为了通过而临时更改reasoning/thinking或增加总预算。模型每阶段既有重试/结构修复上限与原运行器相同；外层不自动重跑整组。案例串行，领域仍采用产品原有并行与独立复核。

dispatch attempt在请求前持久化，每个case保存输入/标签哈希和原始semantic结构输出trace；保存每次尝试的HTTP/finish/error、token usage可用性、预算和起止。截断、HTTP失败与业务不匹配单独计数，缺失usage不补成零。每例前后及全组后核对冻结文件，发生漂移时标无效而不继续评测。

## 验收与解释

保留36/12两组完整分母，以及可评、不可评和未评分数量；三口径均列业务/安全/提案/事实失败。新契约仍须不接受对照错误输出。仅仅修复误判不构成产品成功率提升；若同一raw在新旧评测得分不同，明确为测量差异。prompt改变后的顺序实验不能证明独立因果提升。

当前发布目标仍要求完整场景、多轮恢复、新未见集、容量与交付验收；这48个已见/实现知情案例不能替代这些要求。G9F单订阅真实浏览器通过是历史场景证据，不能自动代表G9G全部能力或本轮六域UI通过。

## 数据库隔离

本轮全仓通过新入口创建随机独立测试数据库，仅初始化测试所需认证表，不seed演示账户。所有子进程显式使用该数据库，运行后只删除本次已记录owned数据库；退出码和清理结果分别保留。原演示库只读前后摘要核对。若初始化或清理失败，记录失败，不以测试全绿覆盖基础设施残留。
