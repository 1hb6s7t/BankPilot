# G9D：组合式账单问题与展示要求

G9D 修复 G9C 两项已确认确定性回归：口语月度收支汇总被拒绝、最大单笔问题后的流水展示要求被当作第二个问题；同时修复补充集暴露的类别总额加“支持合计的原流水编号”展示表达。G9C 原标签、评分、源码副本及失败证据保持不变，不回填旧成绩。

本次改动仅在原 `queryFromSource` 解析路径中组合已识别的语义片段；期间检索、金额计算、完整性、最大单笔并列、分类比较和流水/周期证据计算保持原逻辑。解析仅使用已绑定的 `SemanticTask.source.text` 与期间原文，不采用模型 canonicalMessage 猜测范围。

## 解析契约

1. 保留引号内名称，按引号外标点读取所有分句。请求动词和礼貌用语在解析问题时处理；展示分句先按其原文验证，不先裁掉关键展示动词。
2. 明确问题可由一个商户/类别总额问题、一个最大单笔问题、原有两个完整月份类别增量比较，或一组互补月度指标组成。收入、支出和净额可跨句组合；“进账/钱进来”“花费/开销/花出去”“最后/最终的净额”属于相应指标语法。指标前缀和数量问法可组合，前缀以最多四个 token 的确定性扫描消费，避免长重复未知输入引发歧义回溯；未登记整句白名单。
3. 同一个问题可以附加展示要求。展示动作包括列出、给出、提供、展示、附上、保留及“我想看到/知道”等形式；对象可组合为金额、合计金额/总额、对应/相应/原始/支持合计或判断的流水编号、明细、引用等。支持对象在前的“把……也列出来”和动词在前的“给出……”两种结构。
4. 明确“按/根据合成账单证据回答”“以合成账单为依据回答”等来源说明属于展示依据。该语法不接受另一个商户、类别、账户、支付渠道、时间段、数值阈值、比例计算或虚构来源。
5. 无标点的“问题并/同时/且/还给出展示字段”仅在引号外、后缀全部满足展示语法时分解。未知后缀保留原文并拒绝；不会先剪掉再回答前半句。
6. 只有全部实质问题都属于同一组月度汇总指标时，多个问题分句才合并为 summary。商户/类别总额、最大单笔与另一项实质查询混合时继续明确 unsupported。只读提醒可组合；限制查询范围的否定或“只看某条件”不能冒充提醒被丢弃。引号外的不要/不看/别查、排除/除了/除……外、仅限等明确约束会被保留并拒绝；引号内同形商户词仍按字面名称处理。

展示要求只决定输出同一查询已有的金额和证据，不新增计算范围。独立金额分组、每个商户分别汇总、排名、均值、退款、按日/周、仅某支付方式等语法尚未支持时，返回 `BILL_QUERY_UNSUPPORTED`、明确 clarification，不产生金额、筛选、流水或证据。没有恢复“未知问题默认整月汇总”的旧兜底。

| 可组合表达 | 必须拒绝的范围变化 |
|---|---|
| 钱进来多少、花出去多少；最后净额是多少；按合成账单给出 | 钱进来多少、花出去多少；不要统计餐饮 |
| 最大的一笔支出是什么；我想看到金额和那笔原始流水的编号 | 最大的一笔支出是什么；给出排除住房后的流水编号 |
| 交通类别的总支出；给出支持合计的原流水编号 | 交通类别的总支出；给出超过 10 元的流水编号 |
| 一个商户消费多少，并给出金额与对应流水明细 | 一个商户消费多少，并给出另一个类别消费金额 |
| 类别支出多少；这次都只看信息 | 类别支出多少；仅统计现金支付 |

引号内的商户名称可包含连词或“并给出金额”等字面词，不参与问题/展示切分。未加引号的明确类别仍用 category，其他受支持名词仍用透明的 merchant_contains；保留书店/书局的既有受限别称规则。未知定位语法仍会明确拒绝，不承诺识别所有中文自然表达。

## 期间原文与商户字面的绑定

期间移除依据原文坐标，不使用字符串首次替换。有绝对 UTF-16 坐标时，先检查 task.source 和 period.source 均为完整 start/end、非负安全整数、范围长度等于各自 text.length，再计算 period 相对 task 的位置，检查位于 task 内、该切片逐字等于 period.text、且全部位于商户引号外。提供了错误或不完整坐标时直接 unsupported，不退回文本猜测。解析器验证的是所收到的 task/period 内部一致性；完整原消息的绑定仍由上游语义验证负责。

旧 scripted 调用缺少 period 坐标时，只允许唯一一个引号外、完整原文 token 的匹配；同文日期在引号内的商户名称中不是候选。缺少合法匹配、存在多个合法匹配、日期被截成更长数字或具体日的一部分，均明确拒绝。period 有绝对坐标但 task 缺少原点时同样拒绝，不能猜测坐标基准。

对于“商户在/于[期间]消费”的明确时间结构，只在已验证的 period 紧邻边界消费在/于及其空格，不全局移除这些字。其他不明确连接词保留并拒绝。引号必须包住整个商户名；“书店”在、“书店”附近、多个名称引号拼接、残余单边引号等不能作为 merchant_contains 返回伪造零额。

独立审查已先用纯函数复现了 `“7月书店”在7月消费多少` 的真实风险：period 绑定后一个 7 月时，G9C 及补修前 G9D 仍错误删除商户名中的首个同文月份，给出变形 filter 和 complete/0。新测试保留冻结 G9C 的红结果，并要求新实现保留 `7月书店` 名称、只计该商户的 5000 分及原流水；同时有完整年月名称、非零绝对原点及 emoji UTF-16 位置、实际商户名含在的正反配对。

## 金额与证据边界

支持的表达仍只统计服务端提供的选定期间 `OUT` 流水。完整账单无匹配为真实零；局部账单仅报告已提供流水及 partial 提示；缺失账单没有推定零金额。整数分运算、全部最大值并列、完整匹配流水引用及历史周期支持流水不重复计入总额的规则均保留。

展示语法不能绕过账单复核或授权。解释金额和提供引用不构成任何管理或资金动作，不解除未知条件的 unsupported 状态；只读答案的复核呈现门禁由既有 G9C 集成实现继续处理。
