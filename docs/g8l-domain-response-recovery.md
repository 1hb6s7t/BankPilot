# G8L 领域操作丢响应恢复与订阅披露期限

2026-10-24。承接 G8K 的聊天分页和澄清恢复，本阶段处理联系人、卡片、订阅、理财与生活目标页面中“服务端可能已处理，但页面没收到结果”的窗口。资金、回执和授权仍以服务端为准。本阶段没有新增依赖、升级锁文件或接入真实银行。

## 复用与任务分配

复用 PostgreSQL 中已有的 `(user_id, command_id)` 唯一约束、动作表与 `goal_commands` 映射；Hono、Zod、React 和 SimpleWebAuthn 保持现有版本。新增部分是与 BankPilot 业务语义绑定的客户端请求记录、只读查单入口及显示状态合并。授权确认、Passkey 凭据不进入可重发记录。

主控负责共用恢复机制、会话接线、故障注入、整体验证及交付证据；GPT-6.1-sol 高推理 Agent 分别负责服务端归属/只读接口、资金与目标依赖页面；中等推理 Agent 负责联系人、卡片和订阅页面；后续高推理独立 Agent 复核跨模块状态与披露期限。资金和授权事务需要更强的推理检查，管理页面采用边界清晰的独立文件任务。数据库验收串行运行，避免 Better Auth 元数据扫描与临时 schema 清理冲突。

## 已实现的行为

| 范围 | 恢复方式 | 关键约束 |
| --- | --- | --- |
| 联系人称呼、卡片、订阅候选 | 提交前保存原请求编号与完整原内容，返回丢失后查询原编号 | 原请求待核实期间不能换一份参数创建新候选 |
| 赎回准备、目标创建、目标重规划 | 刷新/切页后只读查原记录，显式重试沿用同编号与原内容 | 目标重规划仍绑定原目标及计划版本；不会暗中取消原动作 |
| 确认、强验证、取消、查单 | 出错后 GET 原动作，保留原始错误并展示查到的状态 | 不自动再确认、启动 Passkey 或重发签名 |
| 目标推进 | 出错后读取原目标及其动作投影 | 查询不会继续推进、准备子动作或执行交易 |
| 页面重新进入 | 可操作动作先读取当前详情；读取失败时提供只读重试 | 旧页面缓存不能重新开放未核实的授权入口 |
| 订阅披露 | 原查询授权截止时间随敏感动作返回，页面到时隐藏详情 | 脱敏观察优先于业务更新时间；银行拦截与商户取消保持独立 |

客户端记录位于当前浏览器标签页的 `sessionStorage`，按已登录用户和业务槽位区分。记录成功写入并可读回后才发送准备请求；存储不可用时不提交。恢复面板提供原内容核对、只读查询及显式原内容重试。账号变化会立即失效旧续程；页面卸载和 StrictMode 废弃读取有独立的执行代次保护。

查单区分 `COMMAND_NOT_FOUND` 与一般 `NOT_FOUND`：前者只表示当前用户没有该命令映射，后者也可能是已有映射的关联对象无法读取。网络错误、503、投影失败都不能证明原请求未受理。目标创建可能先提交，再因子动作冲突返回 409，因此单看写请求状态不能丢弃原编号。

首次收到明确拒绝时单独保存拒绝证据；只有之后查单明确确认没有该命令映射，才解除这一笔记录。每次再次发送前清除旧拒绝证据，避免把前次拒绝当作新一次模糊响应的结果。原本是断线等模糊响应的请求，不会因为后来一次重试被拒绝而自动释放原编号。

新入口包括 `/api/management/commands/:commandId`、`/api/investments/commands/:commandId`、`/api/goal-commands/:commandId` 和三个领域的动作详情 GET。均检查归属。原 core/investment `getAction` 会处理过期与释放占额；新增只读选项走 SELECT 与现有视图函数。目标读取只补充当前动作投影，不保存、不推进、不准备、不派发。这里的“只读”指业务处理路径；不把真实登录中间件的会话维护描述为整套数据库绝对零写入。

同一计划的目标合并保留已完成转账证据，并归一目标标题状态；已由服务端确认成功的等待到账节点不能被迟到旧快照撤销。新计划、不同节点版本或不同动作身份不能继承旧回执。预计日期、赎回状态或单独一份赎回回执都不足以在客户端推导等待节点成功。较旧目标列表也不能切走刚创建或恢复后选中的目标。

敏感管理动作包含 `detailsRedacted`；允许展示时包含原查询授权的 `detailsAccessExpiresAt`。所有准备、重放、确认、取消和读取路径使用原授权期限，查询不延长授权。客户端期限缺失、失效、到期或收到脱敏观察时屏蔽商户、金额等敏感明细、回执及相关错误文本，禁用该动作的确认；安全取消仍可用。业务状态和动作 hash 不因显示脱敏而改变。

新增浏览器场景覆盖：联系人准备丢响应且查单不可用后刷新恢复、卡片取消失败后的跨页阻止重复授权、原订阅查询授权恢复、赎回显式同编号重试、目标创建/重规划/推进/付款的原记录恢复、赎回签名丢响应且未到账资金仍占用、提交后子准备冲突、提交前断线后查不到原单、明确拒绝后的解除、新一次模糊重试不能沿用旧拒绝、迟到列表不得改选中目标、订阅明细原地到期及同业务时间的新脱敏观察。

浏览器使用独立临时 schema、真实本地登录/API/PostgreSQL/Worker。故障方法包括真实提交后截断响应、提交前 abort、明确 4xx 响应注入、特定只读请求错误，以及迟到读取和缩短合成授权期限；没有真实银行调用。原始浏览器 afterEach scope 的 `responseLossAfterRealCommit: true` 是过宽的整组标签，不代表 12 例都采用提交后丢响应。最终核验逐例补充 `verifiedFaultMode` 并归一该布尔值，保留原标签和原始报告不覆盖；通过分母、断言和清理结果不变。G8L 场景不需要模型生成。软件 Passkey 使用 Chromium 虚拟认证器和真实签名验证，不是物理设备验收。

保留了中间失败记录：后端首轮 3/4 的失败来自测试资金安排未计入另一笔已授权占额；浏览器首轮 3/6 的失败分别是把脱敏通用回执误断言为整个回执消失、修改目标金额前未显式取消原候选，以及把周六 T+0 误按当天结算。修正测试使其遵守原业务合同，签名恢复场景改用 T+2，检查未到账资金仍占用且不记入现金。另一次 10/11 的失败是通过旧标题文字定位脱敏动作，改为稳定动作 ID 后专项通过。上述失败与后续结果分别保存。

独立复核发现并修复的旧目标列表选择、目标顶层终态、订阅缓存脱敏，以及拒绝证据跨重试失效问题均增加了对应回归。没有把只读代码复核当作运行测试，也没有声称这些新增用例已经在旧版本跑过红测。

## 边界与后续

- 请求记录限于同浏览器标签页存储；关闭标签页/清理存储后仍可从服务端业务列表查到已受理对象，但不能承诺恢复尚未取得服务端结果的原编号。尚无跨设备待恢复命令队列。
- 原响应始终不确定、原参数又持续被拒绝时，保持原编号；本阶段没有实现“服务器撤销尚未受理请求”的持久化协议，也不会直接遗忘编号来放行一笔可能重复的新操作。
- 状态恢复、确定性资金约束及软件签名已在合成环境验证，不等同于所有持久化故障窗口、任意容量、真实模型质量或接收方安装验收。
- 2026-10-24 10:02 上海时间模型目录仍跳转暂停页。诊断用了 2 次目录 HTTP，0 次生成调用，见 [目录诊断](evidence/2026-10-24-g8l-provider-catalog.json)。本阶段不发布新的云端质量分数。
- G8I ZIP 仍是历史交付物；没有将它记为包含 G8L 的新导出包。后续继续真实模型与新未见样本、其他持久化故障窗口、性能容量和接收方/比赛交付，总体目标仍为部分证实。
