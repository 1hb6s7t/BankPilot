# G7 质量修订与保留集验证

日期：2026-10-23。状态：v3 的已知 pilot、保留集首次执行与浏览器首测完成；两项已复现的局部错误已修复，修复后 709/709 自动化、3/3 真实云模型浏览器流程通过。语言质量仍未完成验收。历史首轮报告不覆盖。

## 本轮实现和复用

本轮继续复用 LangGraph、Zod、既有 OpenAI-compatible provider、严格领域解析器和 FinanceService，没有新增依赖或更换模型。共用当前 `.env` 的云端服务；报告只保存端点、模型标识与无凭据诊断。

- 语义层区分完整指令引文与作为名词参数的产品引号；补齐卡尾号、卡状态和商户会员的完整参数边界。独立复核发现的文本改写误提案和尾号否定限定问题已修复。
- 原文校验问题提供静态字段路径、分类和错误码；缺收款人会明确询问收款人。不会自动扩大 scope、猜对象或补金额。新增 39 项合成质量回归，没有复制评测 fixture 原文。
- 语义阶段每次输出请求最多 4,096 token。剩余预算按实际调用的领域阶段和复核阶段、统一重试上限分配；所有允许尝试的请求上限合计最多 32,768，不从 usage=0 或提前成功中退款。
- provider 记录每次请求上限，以及返回时可用的推理长度／token 数值；不保存推理原文。`length` 即使没有可见答案也归类为截断。没有新增 thinking 开关或根据网关猜测修改配置。
- 资金查询直接展示服务端 `spendableMinor`，明确“扣除保护金额后可安排多少”。付款预演另列支出后账户余额；不将账户余额当作可自由安排额度。界面读取同一服务端事实。

开发分工：Astra 处理语义与参数边界；Sol 处理 provider/预算并独立复核语义和主流程；Luna 维护评测协议、分组和 scorer；主 Agent 完成契约、业务集成、资金展示及最终执行。这是开发协作安排，产品运行时仍是总控、按需领域 Agent 与独立复核，使用同一指定云模型。

## 评测协议和解释边界

新协议为 `g7-semantic-eval-v3-success-cardinality-budget-caps`。除阶段预算外，修正了 scorer 对重复成功逻辑阶段的漏检、非法预算数值审计、正常返回但 deadline/input integrity 失效时的 run-validity 判定。保留首次失败、所有尝试和增量 JSONL。v2 是本轮实现过程中的协议草案，未进行云模型评测。详见[修订协议](phase7-refinement-protocol.md)。

原 12 例 pilot 已用于开发，现在只能作已知回归。另 12 例本轮首次执行；实施代理曾看到 manifest 的逐例标签理由，但没有据此读取保留集原文或修改实现，因此不能称为完全盲测。首次执行后，这 12 例同样成为已知样本。fixture 标签、用例及顺序没有改写。

原 v1 每次请求固定 2,048 token，scorer 和源码也不同。因此分别报告 v1 与 v3 的结果，不能用两个分数作严格同条件对照。自动化检查、真实模型、浏览器及交易执行证据分别报告。

## 浏览器首测与局部复测

[首测报告](../evals/results/2026-10-23-g7-refinement-browser-first.json)为 **1/2 通过**；[3 次计划响应](../evals/results/2026-10-23-g7-refinement-browser-plans.json)独立保存。精确 307.50 元／原备注的待确认转账草稿和刷新后的原计划恢复成功；但“只是个示例”被错误标为 clarification，首个完整流程失败，actions=[]。错误是 `SEMANTIC_QUOTED_ARGUMENT_UNRESOLVED`，不会改报为安全通过案例。

第二个流程验证当前 8,000 元账户、5,000 元保护金额和 3,000 元可安排额度：云端回答与服务端事实一致、无新增动作、账户不变，桌面与 390px 移动端可见且无横向溢出。[桌面截图](evidence/phase7-refinement-funds-desktop.png)、[移动截图](evidence/phase7-refinement-funds-mobile.png)已实际查看。

## 完整项目边界

本轮没有授权或执行真实资金操作。模型评测的安全数字仅指规划提案；不能代替 Core、授权、Worker 和账本验收。709 项自动化通过也不等于语言泛化或完整项目验收通过。

完整对话持久化、澄清续接仍是 G8 的待实施项，现有 [G8 契约](phase8-contract.md)和[复用方案](phase8-reuse.md)是设计文档。先保留当前质量问题及证据，再按[完整验收基线](ideal-state-acceptance.md)推进；本轮不将完整项目标为完成。
