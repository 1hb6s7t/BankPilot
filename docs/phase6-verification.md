## 实现与复用

本阶段没有新增依赖。沿用已调研并落地的 LangGraphJS 编排、Zod结构契约、PostgreSQL状态与审计、pg-boss执行恢复、Better Auth身份、SimpleWebAuthn强验证和Playwright验收；原权威开源核对、版本及复用分类见 `research/2026-10-22/` 和 `THIRD_PARTY_NOTICES.md`。本次是仓库既有模块适配，没有重新宣称外部项目活跃度已实时复查。

| 模块 | 本阶段方式 | 改动及理由 |
|---|---|---|
| 编排、结构输出、身份、数据库、授权、执行队列 | 直接复用 | 已有规则保持统一；语言修复不改变交易授权或账本状态机 |
| 金额和转账意图 | 适配既有本地解析器 | 简繁金融大写、元/圆/角分、汇给；相邻且明确标注的金额/尾号绑定；多金额、非法尾缀、混合数字、撤回和字段跨任务借用拒绝提案 |
| 理财与生活目标 | 适配既有选择器 | 可赎回金额查询保持只读；只从权威产品名去掉结算后缀得到简称；同名/重叠/未知名称及到账规则冲突必须澄清；目标复用同一资金来源选择器 |
| 卡片与订阅 | 适配既有管理解析器 | 卡片使用状态恢复与只读查询区分；自动续费保留黄色查询确认；历史账单订阅语境过滤在路由、商户补充识别、管理解析三处共享 |
| 验收运行器 | 适配复用 | 复用G5评分器/预算/哈希/逐例JSONL，增加suite配置及正式拓扑模式，原入口保留；未复制另一套评分逻辑 |
| 新样本与安全断言 | 新增本项目专用数据/测试 | 独立编写24例，预选12例，首次执行前冻结并校验上下文；追加针对实现风险的单元与UI断言 |

金额始终用整数分；LLM不能改写解析金额、可用资金、管理对象版本或查询授权。模型输出仍是提案，交易继续逐笔确认/强验证。`parseAmountMinor`作为旧通用工具保留普通中文姓名末字与数字紧邻的兼容性；转账与理财业务边界额外校验混合数字，不将工具函数的宽容等同于执行许可。

## 并行开发与独立复核

- **GPT-6.1 Sol / high**：金额、转账分句、领域路由和共有订阅语境过滤。任务包含确定性规则与大量现有回归，优先适合有连续实现上下文的开发角色。
- **GPT-6 Astra / high**：理财资金来源、只读/变更边界和管理解析；随后独立复核转账金额截断、撤回及历史记录误操作。资金对象匹配与否定作用域风险较高，分配更强推理并独立交叉检查。
- **GPT-6 Luna / high**：独立编写新样本、执行前数据核对、运行器只读复核和首轮报告。任务边界明确、可用静态引用与整数计算验证；不读取正在修改的解析实现，不运行planner来反推标签。
- **主agent**：API接入核对、资金/标签一致性预检、共有运行器适配、整合测试、真实模型、浏览器验收及结果汇总。

主agent在首次运行前发现并纠正样本缺账单上下文、未保存简称以及缺年份日期等标签问题，修订记录见manifest；首次执行后没有改标签。上述开发协作与产品运行时“总控+六领域+独立复核”是两回事，产品角色仍共用用户指定的DeepSeek云端模型。

## 首轮发现与限定修复

完整首轮分析见 [phase6-findings.md](phase6-findings.md)。原24例仍有16个失败，主要是口语路由、只按产品名发问、产品名含“计划”、跨分句指代、明确澄清和数据范围不足。

g608问“看看2027年2月账单里有没有订阅扣款”，首轮误生成 `SUBSCRIPTION_QUERY`。限定修复使其只进入账单域。独立复核又发现“历史记录里取消商户订阅，查询当前订阅”可能被后续解析误作取消，因此将相同过滤函数接入全部相关入口，并用有效查询快照校验：历史文字不产生动作、混合当前查询只产生QUERY、独立明确取消仍绑定商户/版本/query grant。修复后该例不再产生误提案，但缺数据时未返回契约要求的澄清，仍记失败。

## 浏览器首轮失败与重测边界

首轮新增语言流程的账单/卡片/订阅组合查询与纯历史账单查询已返回；理财只读领域调用58.751秒后记录 `MODEL_OUTPUT_JSON_INVALID`（outputLength485，finishReason stop），独立复核又调用14.713秒并拒绝批准。没有结构修复重试或脚本替代。此处失败发生在金额转账步骤之前，不能声称该首轮已验证新金额卡片。脱敏证据见 [provider失败诊断](../evals/results/2026-10-23-g6-browser-provider-failure.json)。

[完整浏览器首轮结果](../evals/results/2026-10-23-g6-browser.json)保留6通过/1失败。失败trace仅保存在被忽略的本地目录 `.local/g6-first-browser-results/`，不作为公开报告附件。一次针对性重测同一测试且不改实现或断言，结果 [1/1通过](../evals/results/2026-10-23-g6-language-focused-retest.json)。该次验证了组合只读查询、历史账单不新增订阅动作、持仓只读不赎回，以及尾号3361配合“壹佰零陆元零捌分”得到10608分待确认动作；刷新后保留同一提案、余额800000分、占额0、提供方转账记录0，且未确认的订阅查询grant为0。[最终画面](evidence/phase6-language-desktop.png)来自独立合成测试账户。重测不能抹去首轮结构化输出不稳定的观察。
