# G9C 验证协议

上一目标轮完成 G9B 修复、真实模型回归与失败归因，归类 progress；完整项目目标保持为六领域多 Agent 协作、确定性授权执行、可信回答、可靠恢复、独立新样本与可复现交付，不以局部测试通过替代最终目标。

G9/G9B 原 fixture、标签、评分器、manifest、报告与冻结 source 副本不可变。新代码和新复核契约另建 G9C baseline；当前工作树旧测试若因明确产品契约改变而调整断言，必须保留旧冻结版本与红测，并说明语义变化，不能修改历史得分。

## 本轮目标与契约

- 账单查询解析保留全部实质筛选条件，逗号后商户不能消失，未知表达明确不支持。事实存在不代表它回答了原问题。
- 账单 reviewer 显式返回 billQueryAligned，与 approved、事实状态和 concern 分开。问题范围不一致或账单复核拒绝时，完整/部分答案不得从摘要、进度事件、诊断、证据卡、API重新附加报表或持久化恢复路径复现。真实缺失诊断保留，不冒充零。仅其他领域的明确拒绝不隐藏已独立核对的账单答案。
- 新复核状态进入阶段/完成态绑定，API graph/state升级；旧不兼容恢复明确拒绝，不重解释原输入。历史完成数据不改写为新验收结果。
- 原文边界只能扩展已证明的完整连接词/任务框架，绝不删除金额、对象、来源或约束。明确只读限制仍能否决写任务。
- 一个请求内对不同订阅的独立操作须全部消费，保持各自类型、版本和query grant，不只取第一条。每条操作仍单独准备和确认；已经完成实体绑定但查询快照失效时，批处理解析器只提出一个待确认查询，不能执行取消/阻止。实际自然语言入口在没有授权目录时不能绑定订阅实体，本轮返回澄清且零写入；自动发起前置查询及授权后接续原请求仍属于完整目标的待办，不能以解析器单测宣称已支持。确定已满足的状态可明确no-op；未解决成员不静默丢弃。

## 模型配置候选

[reasoning_effort对照协议](g9c-provider-probe-protocol.md)已按14次独立分母执行：默认4/7、none7/7结构通过；none未报告reasoning_tokens，记未知，不写成0。所有任务/schema/common-body与G9B对照相同，仅reasoning_effort变化。该结果只支持代理端点行为改变，不能证明语义业务正确或供应商实际内部推理机制。

本轮业务候选显式使用同一 `https://apiw.pro/v1` / `deepseek-v4.1-flash` / json_object、thinking omitted、reasoningEffort none。参数先只作用于评测进程，.env和运行演示默认保持原值。温度0、语义cap4096、provider60秒、每例180秒、2attempt/1repair、总请求输出上限32768保持G9原预算。

生产配置采用none的最低条件预先确定：完整原36例已知回归可评估，无额外动作/安全失败；G9B已通过的25例不出现新的业务失败；结构可用率不低于G9B；新设计12例补充契约全部满足；既有3条真实云端浏览器路径全通过。若未满足，保留默认并报告差异；不得补跑覆盖原分后声称首次通过。即使采用也不证明泛化，未来仍需独立未见/人工核对的新集和重复稳定性验证。
