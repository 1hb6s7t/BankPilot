# G9E：理财查询的确定性对象范围

独立只读检查发现，原 `localContext` 即使收到 `investment_query.slots.entityId`，旧 `resolveInvestment` 仍为只读查询构造全部持仓摘要和证据。语义上指定一个对象，并不意味着下游回答真的限定到该对象。

新增 `resolveInvestmentQuery(dashboard, positionId?)`，由 `localContext` 仅在已通过服务端语义校验的理财查询、或目标的筹资来源依赖路径调用。它不解析用户自然语言，不自行选择第一条持仓，不准备赎回动作。

- 无单一对象的集合查询读取快照全部持仓；已存在的空快照明确表示暂无持仓，缺少快照则要求取得数据，不能冒充查询到零。
- 单对象必须在当前快照中精确且唯一匹配 `positionId`。不存在或重复时返回澄清、零证据，不退回其他持仓。
- 领域模型收到的摘要和证据只包含请求范围内产品的本金、预留、可赎回额度和合成到账规则。未请求对象的名称、金额不进入该领域事实。原始服务端快照保持不变。
- 筹资目标的理财依赖只展示其绑定的来源持仓；同一请求同时查询 A、用 B 筹资时，分别标注查询事实与筹资来源事实并合并证据，同一来源去重。全集查询加单一筹资来源保留已请求的全集，不能把 B 的核对遗漏；目标金额和赎回金额仍由既有独立字段/目标验证控制，查询不会产生立即赎回或自动转账。

该函数不执行收益、到期筛选、排序或首条截取；支持范围由同轮语义门禁完整核对。不支持的原文限定必须澄清，不能静默删除后改问全量。旧脚本解析入口 `resolveInvestment` 仍保留，不能将本次结构化查询路径修复描述为任意旧字符串查询已经支持所有筛选。

新增 `tests/g9e-investment-query-scope.test.ts` 使用独立产品和第三个未请求对象canary：核对单对象事实、全集、空/缺快照、缺失/重复ID、实际planner的查询与目标依赖context，验证不产生赎回提案。额外覆盖查询 A + 筹资 B、查询 A + 筹资 A、全集查询 + 筹资 B 三种组合。与既有financial测试合计41项通过只是本地纯验证；云端和浏览器需按本轮冻结候选另行验证。
