# G7 初始契约：语言语义入口与结构化规划可靠性

状态：工作范围初稿，供当前实现与独立评审使用；新盲测样本尚未创建/运行。本契约定义验证目标，不预先声称修复成功。G7 是“理想项目状态”路线中的一个阶段，不替代聊天恢复、六领域整体验收、演示交付或完整项目目标；更大的验收基线见 [ideal-state-acceptance.md](ideal-state-acceptance.md)。

## 目标与边界

G7 处理原始用户中文表达进入既有确定性业务校验之前的语义候选质量。目标是让可识别意图得到恰当领域路由和槽位候选，让缺失/歧义信息明确澄清，并确保后续提案继续服从确定性账户、收款人、金额、资金、版本、授权和执行边界。

本阶段不授予模型银行工具或任意写权限，不放松严格输出Schema，不把模型摘要当资金事实，不改用模型计算余额/预算，不把澄清自动补成授权。对不在可核实合成上下文中的信息应说明缺失并询问；不能凭用户口语或模型常识发明账户、产品、日期年份、账单月份流水、商户授权或历史对话状态。

本阶段暂不实现：完整聊天全文持久化、任意中途 LangGraph 检查点恢复、跨设备线程恢复、真实银行/商户接入、生产可用性/SLO。它们仍在完整项目 backlog 中；恢复设计应见总体基线，不因 G7 范围小而删除。

## 待覆盖意图与语义约束

1. **动作意图 vs 只读查询：** 区分“有哪些持仓/现在可取多少”与“赎回”；区分卡状态、订阅清单或账单查询与挂失、取消、银行拦截等变更请求；产品名称中含“计划”等字面词时不得误识别为生活目标。
2. **名称绑定：** 只接受上下文中确切姓名、明确保存的别名、满足契约的尾号/机构限定。未经登记的简称、模糊指代、同名实体或已过期快照必须澄清。不能用语义相似度直接选择金融资源。
3. **金额和日期槽位：** 支持常用口语与中文数额写法，再由确定性解析验证整数最小货币单位；拒绝金额冲突、无单位多值或超过上下文/政策限制。生活目标需明确可解释的完整日期；缺年份不可擅自补当前年份。
4. **跨分句/续接与作用域：** 将“再转给同一人”“金额改为……”仅绑定当前明确的对话上下文。否定、撤销、假设、引用、示例和咨询语句必须在适当作用域内抑制动作提案；未提供会话历史时不得捏造“刚才那笔”。独立肯定请求不借用否定/引用片段里的字段。
5. **数据范围与证据：** 指定月份或比较范围必须有对应已提供的流水/报表。仅有单月上下文时不得编造另一月份结果；无数据时指出缺失并澄清/提示无法回答。账单交易号仅来自上下文证据。
6. **跨域与目标筹资：** 同一句可包含多个明确业务意图，但每域分别使用已校验事实；生日/生活目标中的理财筹资要使用唯一且已知的持仓、明确赎回金额、可用余额和到账时间依赖。未说明来源时不得替用户选择产品或把未到账金额当现金。
7. **结构输出和失败闭合：** 字段、枚举、schema和版本必须完全有效；缺失、冲突、额外字段、拒绝、超时或无效JSON保留清晰失败/澄清诊断，不做隐式删字段、伪造补齐或脚本替代云端成功。复核可以拒绝并说明原因，但不能授权执行。

这些语义维度源于 README 演示路径、phase1–6 遗留缺口及 G6 首轮失败。每条后续 fixture 必须在冻结前手工注明输入提供了哪些依据、期待的领域/动作/槽位、为何需要澄清或为何不能行动；新样本不能从 planner/resolver 输出反向生成标签，也不能与旧 G5/G6 词句或实体简单改写后重称盲测。

## 必须保留的系统边界

- 会话用户和资源归属由服务器确定，Agent 输入不能携带可覆盖的 userId、余额或授权等级。
- 金额用整数最小货币单位；资金限制、账单汇总、产品持仓、费用、到期及动作参数由确定性服务计算并在 API/Core 重新校验。
- 计划、复核与摘要只形成建议或待确认候选。强验证、动作摘要绑定、用户确认、幂等、占额、Worker、原单查询和回执必须走既有执行链。
- 否定、缺数据和歧义的安全停止属于有效行为，但若任务可清楚完成，泛化路由遗漏仍是质量失败；两者需分开评分。
- 结构输出有效率、最终模型调用完成、语义正确、路由覆盖和端到端操作成功分别记录。不能把模型成功返回/脚本通过/安全拒绝合并为业务通过。

## 建议验收协议

正式新集合由实现外的独立审阅者在执行前手工编写与复核，覆盖六领域、单域与跨域、只读/变更、明确/缺字段、否定/引用、续接、名称歧义、金额/日期表达及无数据情形。先冻结所有 fixture 字节、标签、上下文和 live 子集，再运行确定性测试与固定版本真实模型；首轮和修复后回归分开保存，首轮标签不因结果修改。

建议报告至少包含：冻结版本与SHA、样本/预选数、模型与结构模式、路由/零路由分布、领域及复核调用成功/失败、Schema有效、语义断言、澄清质量、意外动作提案、延迟分布（实际调用样本及全量分别列出）、供应商usage、源码起止哈希、逐例失败和浏览器关键路径。评测方案的具体阈值待基线运行和评审后批准；本初稿不发明官方比赛分数。

建议安全门：没有任何不符合标签的金融动作提案；失败时动作仍被确定性边界拦截；模糊和缺信息场景不擅自选资源/补事实；所有报告区分脚本、live模型与真实浏览器/数据库闭环。质量目标需同时检查路由召回与正确执行，不能通过让系统对所有请求都澄清来获得表面安全通过。

## 开源与自建边界

继续复用现有 LangGraphJS、Zod、PostgreSQL、provider adapter 与测试基础设施。语义候选、中文银行语料、收款人/产品上下文策略、金额与日期业务校验、否定/引用作用域、澄清文案、金融动作语义断言属于本项目业务层，不因引入另一套 Agent 框架而自动获得。严格Schema校验和provider诊断沿用现有实现，模型prompt/structured-output reliability 修订须单独报告实际云端验证，不能以类型检查代替模型质量证据。

开发实现结束后先做独立代码评审和针对性自动化检查，再由不参与实现的子任务作者提供未见 fixture。此后冻结、初次运行并报告；该集合一经运行即成为回归集。对话/计划持久化与恢复进入后续单独阶段，需在主业务长期恢复 PoC、身份命名空间及跨刷新/进程重启验收完成后，才能把它从完整项目缺口改为已证实。
