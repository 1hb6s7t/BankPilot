# BankPilot 理想项目状态与验收基线

本文件把项目目标、现有证据和未完成项放在同一张验收基线上，供后续阶段推进完整项目。它不是新的官方竞赛规则，也不是对生产金融系统的认证。项目自身研究将方向定义为：面向生活目标、带资金与时间约束的银行事务 Agent；采用“总控 + 六领域 + 独立复核”，在可变、可复位的合成银行与商户环境中深入展示转账、账单和生活目标主线（见 [开源复用与模块化决策](../research/2026-10-22/BankPilot-开源复用与模块化决策.md)）。README 是当前产品范围和本地演示操作的索引；分阶段验收仍以各阶段实际运行记录为证。比赛组委会的完整正式评分细则未在仓库中，因此文中“项目目标”与“建议质量门槛”不会冒充官方强制条款。

状态含义：**已证实**指存在可定位的实现和对应测试/演示证据；**部分证实**指只覆盖合成环境、单路径或固定样本；**未证实/缺失**指没有足以支撑该结论的当前证据。历史阶段报告描述其当时源码；若没有当前版本重跑或哈希对应，不自动视为当前回归通过。

## 独立于正式项目要求的建议质量门槛

以下是建议采用的内部质量目标，不是仓库已达成事实或已知竞赛硬性条款：

- 关键负向及授权边界用例不得出现不符合标签的动作提案；任何自动化交易写入必须有独立确定性授权和可审计状态。
- 对预先冻结、未见且人工核对的按域分层测试集，分别报告路由命中、语义动作正确、澄清正确、结构有效、模型调用完成、端到端浏览器通过；不合并成一个通过率。
- 恢复门槛以重启/丢响应/重复请求故障注入验证“外部动作最多一次、UNKNOWN 不释放占额、最终回执可找回”，并覆盖会话切换和旧版本提案。
- 性能目标应由评委体验和本地/模型部署条件共同决定；开始测量前明确纳入零调用失败与实际调用两套延迟，禁止把未路由样本解释成快速完成。
- 演示交付需从全新工作区复现设置、登录、六领域导航、主线任务、澄清/失败和刷新恢复，并展示合成环境边界及测试证据。
