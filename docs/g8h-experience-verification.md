## 本阶段发现并完成的修复

1. **生活目标文案与状态。** 将通用目标页面中固定的“生日目标”改为“生活目标”，统一目标内转账状态的中文显示；支持学费等原本已允许的生活目标。金额、日期、风险与授权规则没有因文案调整而改变。
2. **订阅刷新后的显式读取。** 刷新仍先隐藏订阅明细；有成功查询动作时提供“查看已授权订阅”，由本人点击后携带原查询动作读取。服务端继续核验有效期与归属，不新增查询动作、授权证明或模型调用。过期或失效时清除快照并回到重新授权。浏览器证明刷新时 0 次明细 GET，点击后恰好 1 次；到期与跨用户规则另由已有集成测试覆盖。
3. **Worker 初始化失败清理。** 队列启动、消费者注册或首次 Outbox 刷新失败时，清理定时器、等待已有刷新、停止已启动资源，并保留原始错误。12 项故障单测与 1 项真实 PostgreSQL 专项检查了失败后的连接归零、无继续定时刷新、同一空间能重新启动并正常停止。
4. **赎回时间一致性及异步失败恢复。** 浏览器第三轮发现提供方已结算，但本地仍为 SUBMITTING。受理时间与到账时间分别读取时钟，跨越 1 毫秒后违反严格回执一致性检查；首次异步核对又因缺少 `await` 绕过错误处理。现从同一次受理时间计算到账日期，并将首次核验失败纳入既有 UNKNOWN 路径，保留占仓、只查原单。4 项新 PostgreSQL 回归覆盖递增时钟下的 T+0/T+2、异步核验失败恢复、篡改到账时间仍拒绝。原有审计失败测试随这一异常契约调整，仍核对事务回滚、占仓和唯一入账。

没有改变回执核验规则来容忍错误时间，也没有通过延长浏览器等待掩盖失败。最终重新运行了完整六域流程。

## 并行分工与开源复用

开发协作与产品的“总控＋六领域＋独立复核”是两层不同机制。本阶段按风险分工并行开展，接触共享数据库的实际测试统一串行调度：

| 协作者 | 分工 | 分配理由 |
| --- | --- | --- |
| Astra 子 Agent | 隔离认证/数据库/Worker 生命周期、六域受控响应、启动故障与赎回时间问题 | 涉及并发、事务、异步错误和资源清理，需要跨层推理与可复现故障证据 |
| Sol 子 Agent | 转账、卡片、订阅浏览器链路与订阅恢复入口 | 以完整交互、状态呈现、授权边界和账本断言为核心 |
| Luna 子 Agent | 独立只读审查、首次失败核对、冻结哈希与终态证据复核 | 与实现者分离，逐项核查已有契约和声明，发现复杂缺陷后交回主线确认 |
| 主 Agent | 账单/理财/目标主线、集成与串行实跑、运行服务更新、报告收口 | 将分支成果放入同一冻结版本，统一证据口径与用户体验 |

继续直接复用已安装的 Playwright、Vitest、PostgreSQL、pg-boss、Better Auth、SimpleWebAuthn、Hono、LangGraphJS、Zod 和 React/Vite；没有新增依赖。适配复用现有 API、Planner、页面及 Worker，增加隔离启动和受控响应工厂；业务专用的资金、授权、原单恢复与状态一致性仍由项目规则负责。复用分类及选型依据延续[开源复用与模块化决策](../research/2026-10-22/BankPilot-开源复用与模块化决策.md)。

## 资源、运行服务与复现

每例均验证：规划排空、专属 Worker 停止、业务/队列空间删除、临时认证用户删除、端口关闭、归属连接归零、临时目录删除，且清理错误为空。全部测试后 G8H 遗留空间、临时用户和连接为零。演示库测试前后的六项摘要相同：83 个账户、余额总计 65579625 分、41 个动作、22 笔提供方转账、82 个认证用户和 170 个会话。[测试前后记录](evidence/2026-10-23-g8h-runtime-after-tests.json)

随后只对本项目 API 与 Worker 进行正常退出和重新启动，加载冻结版源码，页面继续通过 Vite 加载。48 张相关表的重启前后摘要中，46 张完全一致，包括现金、账本、提供方原单、目标、消息、登录与规划命令；另外两张赎回动作/Outbox 表由后台查单更新，原有 6 笔 SETTLING 赎回仍等待结算。没有宣称所有运行中表完全不变，也未重试两条历史过期的 running 规划记录。[服务更新记录](evidence/2026-10-23-g8h-runtime-refresh.json)

已有本地依赖与数据库时，可执行：

```sh
pnpm test:e2e:g8h
pnpm test
pnpm typecheck
pnpm build
```

G8H 浏览器配置不加载 `.env`，只接受本机数据库，测试模型使用固定无效域名；复现时应在合成日历的工作日运行 T+0 即时到账场景。T+2 到期测试通过实例时钟推进完成，不是自然时间长跑。认证使用 Chromium 软件 CTAP2 认证器生成真实签名并由服务端验证，不是实体安全密钥或生物识别验收。

原始 Playwright trace 保留临时测试登录的网络内容，仅用于本地复核；本报告没有将其宣称为已脱敏的公开交付包。测试未加载云密钥。fetch 出口限制只覆盖当前应用的 fetch 路径，不是操作系统级防火墙。终态函数先读服务投影、再读数据库事务快照，跨两者不是同一原子快照；用例先等待稳定终态再逐项核对回执、金额和分录。
