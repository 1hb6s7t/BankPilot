# G8F 领域阶段恢复与目标资金来源

日期：2026-10-23。本阶段延续 [G8E](g8e-model-recovery.md)，处理领域 Agent 或独立复核服务失败后原请求无法继续的问题，并阻止独立赎回被误当作生活目标的资金来源。本轮实现与受控验收已完成：**1417/1417（60 文件）**、类型检查及构建通过，**4/4 受控浏览器**通过，最终冻结 **153 文件**，本地 API 已更新。真实云模型质量仍未完成新的验收。

## 用户行为与实现

同一个请求的语义识别、各领域提案和独立复核分别保存。短暂模型服务故障使请求进入失败状态，用户点击“重试原请求”时复用已成功的阶段，只调用尚未成功的领域或复核。即使没有启用图检查点，这些成功阶段也由数据库保存，不依赖 API 进程内存。检查点开启时，已明确结束的服务故障创建新的图运行，读取同一请求的已成功阶段；进程中断留下的可信检查点仍通过原有租约转移机制继续。

并行节点中一个快速失败后，系统等待已经开始的其他节点结束并保存结果，再提交请求的失败状态。永久错误优先于临时错误，避免用户无休止重试已经不能恢复的候选。复核必须等待完整领域结果，不在失败分支仍未解决时生成可消费提案。

成功缓存绑定冻结输入、图与状态版本、角色及该阶段依赖摘要，缓存结果和独立成功记录交叉校验。损坏内容、缺失结果、缺失历史、错误版本及另一个请求的缓存会停止恢复。每个写入继续使用当前命令租约；过期进程的迟到结果不能覆盖新结果。累计输出请求上限仍为 32768 tokens，未知尝试不退款；缓存阶段不产生新的模型尝试，后续预算只分配给尚需调用的阶段。

模型服务失败、协议/结构错误及违反请求约束的候选属于系统失败；真实信息缺失、确定性资金不足和有效的复核否决仍是完成的业务结果。交易草稿仍须另行授权；阶段恢复不会执行或授权付款。历史 `complete` 结果保持回放，旧图版本的不兼容未完成快照明确停止，不自动重新解释用户原文。

生活目标校验使用原始文字中的对象、两组金额、截止日及资金关系。例如“先赎回用于这笔学费”可形成目标依赖；“另行独立赎回”“这笔赎回与目标无关”不能被合并进去。不能安全表示的组合继续澄清。此次没有把模型返回的 transfer 自动改成 goal，也没有删除日期或资金来源让错误候选通过；详见 [目标资金来源专项](g8f-goal-funding.md)。

## 复用方案与并行分工

不增加依赖、不更换指定云模型、不更改评分标签。上游项目的活跃度、许可证及维护证据沿用已有[权威开源调研](../research/2026-10-22/BankPilot-开源复用与模块化决策.md)和 [G8 复用清单](phase8-reuse.md)；本阶段验证本地固定版本的实际能力，没有宣称重新核验上游当前活跃度。

| 优先级 | 模块 | 分类及具体复用 | 本项目必须承担的部分 |
|---|---|---|---|
| P0 | 并行规划与检查点 | 适配复用 LangGraphJS、PostgresSaver 及现有检查点租约隔离 | 定义已结束服务故障与进程中断的不同恢复语义 |
| P0 | 阶段持久化 | 适配复用 PostgreSQL 事务、行锁、现有命令及调用 journal | 阶段缓存、输入/依赖/版本绑定、成功历史校验及永久错误优先 |
| P0 | 输出验证与预算 | 适配复用 Zod、已有请求专用 schema、provider 有界修复与调用预留 | 业务结果和系统失败分类、只给未完成阶段分配预算 |
| P0 | 资金来源关系 | 适配复用原文定位、金额与实体落地校验 | 开发目标与独立赎回的关系守卫；不能由通用框架推断授权 |
| P1 | 恢复界面 | 复用现有 React/assistant-ui 失败投影及同命令重试入口 | 通过实际浏览器验证刷新后状态和确认卡归属 |
| P1 | 验收 | 直接复用 Vitest、Playwright、现有隔离 PG/进程 fixture | 注入并行故障、租约接管、缓存损坏，并检查资金和调用记录 |

开发采用三条并行工作线：Astra 负责阶段状态、并发租约、预算和检查点实现，因这些变更直接影响恢复正确性；Sol 负责生活目标语义及反例，独立于编排改动；Luna 只读审查实现与验收边界。主 Agent 独立编写 API/PG 和浏览器验收、整合回归与冻结证据。开发分工与产品中的总控、六领域和复核 Agent 是两层机制。

## 验收过程记录

- [初始 API 红测](../evals/results/2026-10-23-g8f-api-initial-tests.json)为 1/7：六种旧服务故障仍返回 complete，证实本阶段需要的状态变更。
- 首批实现后的 [11/11 API/PG](../evals/results/2026-10-23-g8f-api-m2-tests.json)覆盖同命令恢复、复核单独重试、快失败/慢成功分支、并发重试、租约接管、提案保存后首个草稿创建前中断，以及旧 complete 历史回放。
- [扩展首次 18/22](../evals/results/2026-10-23-g8f-api-extended-tests.json)的四个失败是错误码预期不准确：一般结构有效但金额、收款人、备注或必需建议不匹配的候选，已被 provider 的请求专用 schema 提前拒收，实际为 MODEL_SCHEMA_INVALID，经过两次有界修复后终止。测试改为核对这一更早的校验边界，保留不复核、不澄清、不创建草稿及不再次重试的要求。
- 独立审查发现公共失败记录只包含被选中的失败分支。新增断言在 [20/22 红测](../evals/results/2026-10-23-g8f-api-failure-history-red.json)复现：并行失败时遗漏其他领域和已成功语义的 ModelRun；逐次预留账本仍完整，不能把这个问题描述为未记录调用或重复付款。

全量首轮 [1413/1417](../evals/results/2026-10-23-g8f-candidate-tests.json)的四项失败也是旧契约预期：修改来源备注的候选，以及三种拓扑对否定请求生成不当澄清，原来返回普通拒收 PlanResult，现在必须抛出永久系统失败。修订保留具体拒收原因，并增加不启动复核、不形成用户澄清、无可消费 PlanResult 和失败调用记录的断言；未改生产校验来迎合旧测试。

## 仍需完成的整体目标

受控故障与本地合成业务测试不等于真实云模型质量。G8E 的真实云接入 0/1 与目录暂停页证据保留，本阶段没有重复调用该服务来挑选成功样本，也没有更换服务商或模型。G8D 的 19/24 仍只是历史已知回归；G8F 的新语义规则尚需指定模型验证，以及实现稳定后独立冻结的未见样本。

下一轮质量评测前必须适配旧评测器对 PlanningStageFailure 的记录方式：目前三个入口会把它记成 EVAL_RUN_ERROR，部分调用、usage 和“有调用案例”延迟只从返回 PlanResult 统计，可能遗漏抛异常的案例。G7 独立 attempts 日志仍保存派发证据；不能把缺少返回结果解释为零调用。该缺口尚未在 G8F 修改，已列入 [G8G 评测准备](g8g-evaluation-readiness.md)。

数据库物理故障、提交响应未知、所有进程中断时点、长历史/并发性能、六领域完整演示、清洁环境复现及正式竞赛交付仍在[理想状态验收基线](ideal-state-acceptance.md)中追踪。本阶段的检查点和 API 测试仅支持所列故障窗口，不声称任意故障都已验收。
