时间：2026-10-22，Asia/Shanghai。本阶段范围为 G0 依赖环境、G1 并行编排/持久化验证、G2 授权转账闭环。不是六场景比赛作品的最终验收。

## 交付状态

实际运行地址：`http://localhost:5178`。Hono API 监听 127.0.0.1:8787，独立 pg-boss Worker 运行。PostgreSQL 17.11 位于 BankPilot 独立 Compose 项目，端口 55432，镜像摘要固定在 compose.yaml。Node 24.19.0，pnpm 11.25.0；npm 依赖精确版本和依赖树已锁定。

默认模式为 **scripted**，使用真实 LangGraph 图、真实 PostgreSQL 和真实 WebAuthn 库，领域推理内容由脚本提供。真实模型适配器已编写，但只验证了模拟 HTTP 协议、结构解析与错误处理，没有调用真实供应商模型。

## 联调中发现并修复

1. 旧前端提案覆盖最新服务器动作状态：以 dashboard 返回值为权威，并将 AUTHORIZED 纳入自动轮询。
2. 日期格式同时使用 dateStyle 与 weekday 导致登录后渲染失败：修复格式选项并加入错误边界，浏览器重测通过。
3. 创建动作已成功、计划结果未保存时发生故障：先保存提案快照，再创建动作；恢复使用原快照，租约令牌阻止旧运行覆盖新结果。真实数据库故障回归证明重试只调用一次 planner。
4. 黄档确认期间累计金额变化：返回新版红档动作，并明确提示重新核对与强验证。
5. 最终状态卡仍显示待授权提示：终态显示已完成或历史风险要求，增加收款银行与脱敏尾号。
