# G7：语义入口与结构可靠性验证

状态：实现、交叉评审、自动化和首轮真实模型/浏览器验证已完成；**真实模型语言质量未达标，G7 尚未通过整体质量验收**。完整项目目标仍见 [理想状态验收清单](ideal-state-acceptance.md)，本文件不代表项目全部验收完成。

## 变更

生产模型路径现在先解释原始用户意图，输出操作候选和原文片段；服务器根据原文、已保存实体目录、完整金额/日期词元和字段关系验证候选，再调用相关领域和独立复核。金额仍由程序计算整数分，授权与执行仍走原 Core。API 只解释一次，取账单/资金数据后复用同一结果；公共请求无法提交内部语义字段。复核能看到原文与已校验任务。目标内赎回依赖只触发理财只读分析，不创建独立赎回。

模型 JSON/schema 错误允许在既有 maxAttempts 总预算内一次完整重生成；原失败、全部 token/耗时和后续结果均保留。禁止部分 JSON 修补、金额修补和云端失败后伪装脚本成功。API 规划的模型调用共享 180 秒绝对 deadline，恢复 lease 为 4 分钟。转账备注也绑定原文并参与提案一致性校验。

## 首轮真实模型协议

独立作者在未读取 G7 实现、未运行 planner/model 的条件下编写 24 例，六领域各 4 例，预选每域 2 例构成 live12。首次执行前类型检查发现一项不支持的账单分类，修正为合法分类并重新冻结；旧摘要、修正原因、时间记录于 [manifest](../evals/g7-manifest.json)。不根据执行结果调整标签。

固定生产拓扑（语义入口→相关领域并行→独立复核）；指定云端模型与现有 JSON 模式；temperature=0；每例 180 秒，总尝试次数 2，每次 max_tokens=2048，保守总输出请求上限 32768。没有把未路由样本当作速度快，也没有把 schema 通过当语义通过。澄清可在语义入口发现歧义，也可在已明确路由后由领域发现缺数据；两种合法路径分别评分。首轮每例写入 JSONL，结束核对源码哈希，不进行结果选择性重跑。
