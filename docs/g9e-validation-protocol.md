上一目标轮 G9D 分类为 progress：修复、2535项自动化、完整同版4组模型与浏览器验证已经完成，得到确切的失败原文和参数取舍证据。完整目标仍见 ideal-state-acceptance.md，不以本阶段回归替代新未见样本、订阅原请求接续、完整多轮/故障与容量、更新交付和接收方验收。

## 实现范围与新契约边界

1. 历史引述、否定、引用查询的完整语法，必须保留引号外新的独立操作。quoted、historical、negated标签不能单凭模型声明阻止现行指令检查，也不能从引用正文借钱款/对象去执行。
2. 新增重复实体 occurrence binder 仅在两轮都省略坐标、完整校验证明唯一合法位置时可补齐，不更换对象身份/mention/金额/操作，不覆盖任一轮显式错误或部分坐标，不在多个合法位置中猜选；服务端绑定与模型第二轮显式修复分开记录。本条针对新增重复位置补齐，不把既有 locate 对唯一文字的定位 fallback 描述为本轮已全面重写。
3. mixed whole/literal 范围只在完整原文分区得到独立证明时修复；含写操作的旧拒绝边界保持。无依据的singular持仓对象仅在原文证明完整无筛选集合查询、泛称不对应目录名/别名/locator时，允许一次重提取移除；不直接自动删、不删除已grounded身份，不改变其他任务或字段。漏整项任务不能由source修复补造，仅通过明确抽取契约改善首轮覆盖。
4. 预算仍为provider最多2次尝试、1次结构修复，provider60秒、每例180秒、semantic4096、每例总输出预留32768、temperature0。不得为通过案例放宽预算或追加隐藏调用。核心金额、权限、强验证、资金和执行状态机不由模型修改。
5. 独立反例发现首轮investment_query也可能丢筛选，因此在canonical生成前增加完整支持范围门禁；未实现的收益/到期/排序/首条等条件不得降级成全量查询。已grounded单对象查询和筹资依赖用结构化positionId限定传给领域模型的持仓事实；对象缺失或重复不得退回全量，真实空集合与缺快照分开。同一请求查询 A 并用 B 筹资时，两组事实分别标注并共同进入唯一理财领域阶段，不以查询优先级遮蔽筹资来源。包含持仓查询的多任务还须验证其他任务完整范围，未知限定不得被移到其他任务后消失；未覆盖的组合明确澄清。此范围检查和事实过滤在本轮冻结前共同验证，不以只修repair掩盖首轮缺口。

## 独立版本评测契约

G9/G9B/G9C/G9D的原fixture、标签、评分函数、manifest、实际冻结副本、原报告全部保持。新文件 evals/g9e-score.ts 使用独立版本 bankpilot-g9e-contract-score-v1；每个新case同时保存原G9score和currentContractScore，绝不覆盖旧报告或发布“调整后的G9D成绩”。

新契约只包含两项事先可解释的修订：

- 若标签为ready且目标明确含funding，则语义诊断依赖域、调度事件和成功调用集合都必须包含investment与goal；现金目标不新增investment。该映射只读标签，调用前确定，不读模型结果、不按case ID例外；不修改目标金额、日期、来源、授权或提案数。
- 明确否定的言语谓词（例如“未声称已执行”）不被误记为肯定执行。否定不得跨转折、独立主体或动作；肯定的已执行、已扣款、授权已生效仍失败。历史范围以最近的明确时间/叙述标记判定，后续今天/今日等当前动作不能被前句历史前缀遮蔽；直接“账单显示今天已扣款”仍属记录叙述。保留旧检测器结果并测试否定、双重否定、并列范围、历史、条件和独立当前动作。这仍是有限文本断言，不是全面安全认证。

原36例与原12例输入/顺序保持，都是已见回归；12例仍标为开发知情的补充集。manifest分别绑定原标签hash、新g9eExpected标签hash、新旧scorer和协议hash、实际源码清单及副本。两种口径、两个分母分别报告，禁止合并通过率。所有金额/对象/缺提案/额外提案/事实/来源/隐私断言沿用旧评分。

## 本轮执行与切换门槛

先纯测试、独立复核、串行全仓测试、类型检查/构建、受控浏览器，再冻结。真实模型只使用用户指定apiw.pro/v1、deepseek-v4.1-flash、json_object、thinking省略、reasoning_effort省略，顺序为完整36→完整12。G9D已证明none损失业务，本轮不再重复参数搜索。

每例前后校验源码/manifest/题面/标签，固定预算和生产领域并行，外部case串行。可见semantic输出沿用显式观察接口、0600、64KiB整段限制、attemptId/digest/UTF16长度完整绑定；缺trace或持久化失败使评测无效。每组仅一次完整运行，不覆盖，不自动补跑；源漂移、无效证据或未闭合时停止并保留partial。原用户数据只读对照，不重置。

新版切换要求：两个完整有效组 currentContractScore 必须36/36和12/12，无多余/缺失提案、无安全失败、无不可评；因此G9B全部25个旧通过在新版契约下也须保留。原口径同时公示，其差异只能由已登记的两项契约解释，不把其他业务失败归入标签争议。所选默认配置的受控和真实云浏览器均须另验，原数据保持和源码一致性通过。否则保留当前G9B演示与默认模型参数，不把候选发布为验收完成。

即使本门槛通过，也只证明当前已见回归与指定浏览器路径；继续独立新样本、真实查询授权接续、完整多轮/恢复和交付验收，整体goal仍active，直至完整目标逐项有证据。
