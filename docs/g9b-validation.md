## 配置与分工

使用用户指定 `https://apiw.pro/v1`、`deepseek-v4.1-flash`、`json_object`。密钥仅由本地 `.env` 读取，证据不包含密钥。配置对照保持 4096 语义输出上限、不重试、不修复，每条件每题一次。

开发并行分工与产品 Agent 拓扑分开：高推理 GPT-6.1-sol 负责原文绑定、否定范围和持仓定位；另一位负责账单证据及结构化复核事实；回归运行器由独立 Agent 复用既有评分与调用账本；GPT-6-sol 负责测试协议适配及只读独立审查，随后处理浏览器发现的具体表单竞态；主 Agent 负责集成、真实服务探针、冻结与验收。资金/来源/恢复边界投入较高推理，机械适配与局部浏览器问题分配给范围明确的独立任务。

## 修复及复用

沿用现有 LangGraph 编排、Zod 校验、确定性账单分析和资金预演、阶段恢复账本、G9 评分器与限额，不另建执行框架。

- 合法备注和用途引用在完整原文证明后作为数据处理，避免其中的其他联系人或命令触发误拒；备注外的收款人歧义仍拒绝。
- 中文实体边界、毛/分金额、斜杠日期和账单期间按完整原文校验；多个任务不得借用槽位、重叠范围或遗漏独立请求。无标点转折支付暂保守澄清，不能静默吞掉正向请求。
- 语义层与财务层共享持仓定位器；T+N 在全部服务端持仓中必须恰好一个候选。含零余额持仓也参与唯一性判断，未知名称残余和截断后缀不准默认选中。
- 周期账单证据支持同一组的多条当前流水，但历史支持流水不重复计入消费。缺失金额使用 null/unknown，已知真实零与部分账单分开。
- 账单复核返回 approved/bill/concerns，展示金额、净额与商户来自服务端证据。独立拒绝仍可阻止提案；伪造引用、错误状态或自由事实文案拒收。
- 账单阶段缓存和最终完成态检查点均绑定新复核版本与事实摘要。API 图身份升级为 G9B/state-v3，旧未完成规划遇到不兼容身份明确拒绝，不静默重解释或重执行；历史完成结果保持历史身份。

详细边界见[冻结协议](g9b-validation-protocol.md)、[账单事实契约](g9b-bill-facts-contract.md)及[独立审查记录](evidence/2026-10-24-g9b-independent-review.json)。
