## Acceptance contract

The first recovery slice is limited to a semantic-intent transport failure for a command that has no saved proposal, result, or side effect. A service failure must remain distinguishable from a user clarification. An explicit retry reuses the same command, root command, revision, original message, and frozen recognition inputs; it gets a new fenced lease and only a bounded amount of remaining model budget. Successful interpretation is a durable stage result: a later Finance/preparation failure must not reinterpret the user request. Existing completed results and proposals retain their current idempotent behavior. Do not infer “service failure” from an empty task list alone: a valid `no_action` result or genuine `clarification` may be complete.
