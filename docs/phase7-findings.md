# Phase 7 semantic holdout findings

## Run and evidence

This is the first live run of the frozen G7 production-semantic pilot. It used the preselected 12-case subset of the 24-case holdout, production parallel domain routing with the independent reviewer, and the configured provider/model recorded in the run artifact. The run started at `2026-10-23T01:14:01.994Z` and finished at `2026-10-23T01:17:35.183Z` (UTC). The manifest and fixture inputs were frozen before execution; their fixture SHA-256 was `b4774491c6eb20dd7cc7f98d2ff302e5ec4f7cf5241c81e57bdea3f8caabca4c`.

The run is complete and valid under its recorded protocol: 12/12 cases have results, `validRun=true`, and `sourceDrift=[]`. The semantic model was invoked 22 times: 18 successful calls and four failed attempts. Eight downstream role-start events occurred in four cases; one retry means there were nine downstream model calls in total. The other eight cases stopped after the semantic router. All 22 calls reported zero input tokens, so the provider's input-usage field is not useful for estimating prompt cost here. Output-token usage was reported for all calls (19,177 total); no raw provider completion was retained, only output length/digest and parsed planner results. This limits diagnosis of parser/validator rejections.

The score is 2/12 against the labels frozen before the run. Structural results were present for 12/12, the scorer recognized the expected intent status/roles in 5/12, the required model-call set completed in 6/12, and downstream business semantics passed in 2/12. There were no scorer-detected planning-safety failures or unexpected action proposals. That safety count does not mean expected proposals were delivered: several expected actions stopped before their domain ran. This evaluation records plans only; no banking action was authorized or executed.

Latency was 9,072.5 ms median and 54,126 ms P95 for all cases; the model-invoked cases have the same distribution because every case invoked the semantic router. The worst latency coincides with provider output exhaustion in the bills case. The protocol fixed every provider request at 2,048 output tokens, independent of fixture labels; the run recorded four failed attempts, including three `MODEL_OUTPUT_EMPTY` and one `MODEL_OUTPUT_TRUNCATED`.

## Failure pattern and limits

The clearest repeated defect is pre-domain rejection of otherwise grounded card, subscription, and transfer requests: `g701`, `g714`, `g715`, and `g718` all stop on span-uniqueness/token/validity findings. `g720` also stops before the subscription domain can produce the expected safe explanation for unsupported merchant cancellation. `g703` demonstrates that stopping safely is not enough when the system fails to identify the missing slot in its clarification. `g712` shows a separate status-classification problem: an ambiguous operation requiring clarification was labeled `no_action`.

Provider output exhaustion independently prevented delivery in `g705` and `g722`. The artifacts do not include raw provider completions, so they cannot distinguish malformed/empty tool arguments from truncation effects beyond the recorded finish reason and error codes. In particular, `SEMANTIC_SPAN_NOT_UNIQUE` in `g701` identifies a validator class but not the specific field it rejected. These causes should remain uncertain until instrumented with privacy-safe rejected-field diagnostics or a suitably redacted raw-output capture.

Only `g708` and `g709` passed. `g724` confirms that a correctly routed domain can still return an incomplete financial answer. The absence of unexpected proposals is reassuring for this small pilot, but it is not evidence that the expected actions were reliably proposed: most actionable cases did not reach a domain. The four provider failures, two successful cases, and this preselected 12-case cohort are descriptive evidence, not a stable quality estimate.

G7 uses new inputs and entities, a semantic-intent router, and a different holdout from the earlier G6 evaluation. Therefore, the G6 and G7 percentages are not a matched quantitative comparison, and this run cannot support a claim of measured improvement or regression between generations. Existing known-fixture regression checks are a separate cohort and do not substitute for this unseen holdout.
