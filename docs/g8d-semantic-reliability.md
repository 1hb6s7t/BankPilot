## 完成的行为变化

1. **两项任务共用了全文范围。** 对明确的“账单查询＋转账”两段原文，先核对已有期间、收款人、金额与唯一分隔，再允许模型只修正两段 scope。第二次候选不得改变任务数量、顺序、任何业务字段或原文覆盖。三任务、条件、否定、引用、不唯一切分以及同时缺其他字段时继续澄清。
2. **用户给出了年月，但模型期间字段不完整。** 单一完整账单任务可针对缺失或无法解析的 period 重新生成，必须对应原文唯一合法完整期间。原文已提供年份时，失败提示改为系统未能准确核对期间，不再反复要求用户补年份。未知原文片段、多个独立期间或缺失年份不猜测。
3. **月度账单被识别为当前可用资金。** 对完整、明确的月度收入/支出/净额短句，允许单独绑定一次 funds_query→bills_query 与原文 period 修复。它不能用于当前余额、生活保护、未来预算或混合请求；其他字段和完整 scope 固定，不能串联第二种修复策略。
4. **卡尾号带容器词被误拒。** 支持“卡／银行卡／卡片尾号四位数字”和“银行卡末四位”，以及保存的完整卡名＋尾号。卡名与尾号冲突、未知名称被裁剪、五位数字截短、同尾号多卡、错误模型 ID 和同范围多个不同尾号继续拒绝。原始 mention 不被改写。
5. **缺少一个月时丢弃已有账单来源。** 仍明确无法比较，但保留已提供月份的报表、真实流水编号及发现来源。partial 报告和行均标注不完整，不生成完整月比较或缺失月零金额。选区外报告、重复 ID、错月/非法金额和缺失引用不进入可信证据。
6. **周期性发现的前月引用。** 对照 FinanceService 的真实生成契约，允许邻接上月同账户、同商户、同金额的 OUT 合成流水支撑当月 RECURRING 发现。上月原始行随发现附带，明确只作佐证；不计入本月 query transactionIds 或金额。非周期性发现不能借用其他月份；同一 ID 的内容必须一致。
7. **整句示例。** 明确整句只是示例时可识别为 no_action。示例后夹带真实请求不能靠一个示例标签吞掉；仍需完整独立范围或澄清。

## 下一阶段优先缺口：服务失败后的同命令重试

除了静态审查，已用本轮同冻结代码的真实 Hono 路由与现有 PostgreSQL 表，独立复现服务失败被归档为 `complete`、`retryable=false` 的问题。[受控探针记录](evidence/2026-10-23-g8d-model-failure-retry-probe.json)使用唯一合成账户、stub session 和仅在该探针进程内生效的模型 fetch：两次返回 502 后，数据库仍保存失败的 semanticIntent、proposal 与 result；模拟上游恢复后重试同一命令，HTTP 返回 200，模型调用数仍为 2，完全重放旧结果。用户输入、金额和对象均无须补充，却收到“请明确当前要办理的操作”的提示。

探针保留 1 条用户消息、1 条助手消息，0 动作；余额 800000 分、占额 0。它证明本地 API/数据库恢复路径存在缺口，**不是修复验收通过**，也不是原 24 例模型评测经过了 API/数据库；未使用真实云端故障、真实认证或浏览器复现。下一阶段须区分用户信息不足和系统可恢复失败，把原文/catalog 不可变输入与失败的阶段输出分开，并保持已有提案及动作的幂等性；只增加重试按钮或把最终状态改为 failed 都不足以解决失败快照的回放。
