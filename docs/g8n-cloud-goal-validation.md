# G8N 目标用途、字段澄清与真实云端验收

日期：2026-10-24。产品仍为本地合成银行；真实云端指调用用户配置的 `https://apiw.pro/v1` / `deepseek-v4.1-flash`，不表示接入真实银行或使用真实资金。

## 本轮问题与实现

G8M 的冻结已知集原始得分是 **20/24**。逐例复核后，四项未通过必须分别解释：

| 案例 | 查明的问题 | 本轮处理 |
|---|---|---|
| g719 银行侧订阅拦截 | 响应已写明“这不会取消商户合同或免除合同义务”，旧评分要求精确子串“不取消商户”，出现字面匹配假阴性 | 保留原响应、原评分与历史 20/24；不为追逐固定措辞修改产品行为 |
| g721 明确日期的生活目标 | 目标在语义校验因 `SEMANTIC_MEMO_INVALID` 提前停止；通用 schema 暴露 memo，校验仅允许转账 memo | 为目标新增独立、可核对原文的可选 purpose，不再把目标用途与转账备注混用 |
| g722 带赎回筹资的目标 | 同一 memo 契约不一致阻止领域规划 | purpose 与目标金额、筹资金额、持仓及其依赖关系分别验证 |
| g723 缺少年份的目标 | 正确停在澄清，但问了已提供的收款人，而没有指出缺少年份 | 在收款人、金额、原文安全与覆盖校验之后，明确请求完整年份；不猜年份、不把 ambiguous 提升为 ready |

旧报告只保存被拒绝模型输出的摘要，不能据此声称看到了原始 memo 的具体内容。诊断码证明校验分支，不能替代缺失的原文证据。旧评分也没有要求生活目标标题必须匹配 gold 标题，保留用途是产品内容改进，而非改评分答案。

purpose 必须是原文中完整、明确附着于目标的名词短语，不得虚构、截断、与收款人/金额/日期/筹资片段重叠或包含操作指令。原文否定、引用、历史、条件和独立操作扫描继续生效。用途只用于标题，不参与金额、执行或授权计算。标题上限直接复用 `goalDraftSchema` 的 80 字约束，81 字用途返回字段明确的 `SEMANTIC_GOAL_PURPOSE_TOO_LONG`，不截断、不 trim 原文。

## 并行分工与独立复核

- 语义与筹资关系任务分给 GPT-6.1-sol / xhigh，负责用途、原文绑定、日期与歧义优先级；这些变更可能影响资金动作意图，需要较深推理与边界回归。
- 管理动作事实审计与固定模型评测分给 GPT-6.1-sol / high，先定位 g719 的评分假阴性，再运行冻结评测；不修改管理语义、fixture 或评分器。
- 独立 reviewer 使用 GPT-6.1-sol / high，只读核对实现与云端夹具，发现并复现 100/80 字标题契约不一致；修正后独立通过 299 项检查。
- 主 Agent 负责类型契约、领域标题接入、真实云端浏览器夹具、串行数据库验收、版本冻结及证据汇总。开发协作分工与产品本身“总控＋六领域＋独立复核”分别记录。

## 完整日期的原文绑定重生

v3 对原文已有完整日期而模型日期槽位错误的情况增加一次受限重生。资格要求：单个明确请求的生活目标，完整原文 scope，唯一且有效的完整截止日期；把原文日期作为临时候选预验证后，收款人、金额、用途、筹资来源及依赖关系必须全部通过已有校验。该临时候选只决定是否可重生，不能直接成为产品结果，也不会作为程序补好的答案传给模型。

模型必须在同一 `invokeStructured` 的原有尝试次数、一次结构修复、截止时间和输出预算内重新输出。第二次深比较所有非日期字段（包括 scope、offset、任务顺序、金额与 funding），完整重验且必须与资格预验证的结果一致。漂移、再次无效、真实缺年、多个日期或其他歧义继续停止。缺年日期若只多包了纯截止措辞，可以更准确地提示年份；这只是诊断改进，不触发生成操作。

[v3 冻结清单](../evals/baselines/g8n-candidate-v3-2026-10-24T03-32-30-717Z/source-manifest.json)包含 206 文件。该候选的语义 Agent 完成 372 项相关纯测试；另一名 Agent 独立完成 219 项交叉复核。两组有重叠，不相加作为测试总数；最终全仓分母另行记录。

v3 全量测试 **1833/1833** 于 03:33:19 UTC 完成。随后末轮否例复核发现日期重生还需排除同域余额问句、第二个目标和等待收入到账的条件；03:33:40 UTC 收紧了资格。此时 v3 模型评测已启动，因此主动停止并保留 [v3 中断审计](evidence/2026-10-24-g8n-model-validation-v3-interrupted.json)：前三项通过，第四项人为中断，8 次请求起止闭合，语义文件及新测试文件发生漂移。该中断轮不计为最终同版验收，也不归因为供应商超时。v3 的已完成自动测试仍只属于此前源码。

最后三项只缩小允许重生的请求范围，修复前有 3 项 mock 请求次数断言失败，修复后 375/375 相关纯测试通过；独立 reviewer 又验证了新增日期修复 76/76。所有开发 Agent 明确停止源码写入后，重新生成 [v4 冻结清单](../evals/baselines/g8n-candidate-v4-2026-10-24T03-36-19-989Z/source-manifest.json)，后续统一以此版本验收。

## 验收边界

24 个固定案例都已经暴露给开发，属于已知回归，不是盲测或新未见集。真实云端浏览器使用独立合成用户、隔离 PostgreSQL schema、真实本地 API/Worker 和 Chromium；资金动作不获得测试自动授权。订阅案例只显式确认独立查询，再检查银行侧拦截候选与商户合同说明。

默认浏览器验收继续使用受控模型；只有专用 `pnpm test:e2e:g8n:live` 加载本机 `.env` 并显式启用真实云端。夹具只放行配置中完整 HTTPS completion 地址，拒绝重定向，证据不记录密钥或云请求头。实际清理成功以每例 `cleanup.json` 为准。

未见样本泛化、全部真实模型业务链、容量与长尾时延、新版本导出、接收方验收和比赛提交仍是独立后续工作；G8I ZIP 继续作为历史交付基线。
