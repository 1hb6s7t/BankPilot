# G9C：原文账单查询范围契约

本次修复只扩展现有确定性查询解析器，保留原期间检索、BigInt 分金额计算、服务端账单覆盖状态、流水校验和周期证据计算。历史 G9/G9B 题目、标签、评分器、源码副本和结果不变；新测试通过不改变 G9B 已知回归 25/36，也不代表新未见样本或真实模型验收通过。

## 原文与筛选

查询仅从 `SemanticTask.source.text` 及已校验的 `billPeriod.source.text` 识别，不采用模型 `canonicalMessage` 中的筛选猜测。期间原文从问题中移除后，按引号外的自然标点解析全部分句。只有明确的请求上下文、流水展示要求和受支持的禁止动作说明可作为附属分句；额外问题或无法识别的条件必须返回 `unsupported`，不再丢弃逗号之后的内容。

支持一个直接修饰“消费/支出”的商户或类别，以及“一共/总共/合计/总计/共扣了我多少钱”“花了多少钱”等完整金额谓词。谓词必须消费完整问题；后缀筛选和未知谓词不能退回整月汇总。含“准确/详细/清楚”的请求动词作为请求措辞处理，商户名称中的“准确”保留。未明确支持的账户、支付渠道、时间段、排序和比例条件返回明确 `unsupported`，不生成伪商户或发布整月金额。该有限语法不承诺识别所有中文表达；例如“我在某店消费多少”目前明确拒绝，避免误把“我在某店”当商户报零。

类别仅匹配现有类别枚举；其他直接名词按显式 `merchant_contains` 规则查询。引号内名称保留标点、连词和字面类别词，始终按商户名称匹配。原有未加引号的“书店/书局”名称别称规则继续透明显示，不扩展全名或引号名称。

## 金额、完整性与证据

只汇总选定期间内匹配的 `OUT` 流水；同名 `IN`、同类别其他商户及期间外流水不进入总额。使用整数分计算，支持超出浮点整数精度的金额。`transactionIds` 列出全部匹配的当前流水；周期发现的上期支持流水仅作为证据，标明 `finding-support-only;excluded-from-query-total`，不重复计入消费。

完整账单无匹配时返回真实零；缺失账单返回 `missing_data`，没有金额；不完整账单返回 `partial`，明确仅统计已提供流水，包括局部零。原最大单笔并列、类别增量比较、完整月份选择和周期证据校验均保留。

## 验证边界

新增 `tests/g9c-bill-query.test.ts` 使用独立合成账单和商户/类别正反配对，包含已知逗号失败的回归、不同标点、请求副词、字面引号、未知谓词、额外筛选、精确分计算、零/缺失/局部覆盖和周期证据。测试不读取 `.env`，不调用模型、银行服务或数据库。只读呈现的复核拒绝门禁由独立 G9C 集成改动处理，不属于本解析器文件的实现范围。
